# ADR-003 统一请求响应协议

- 状态：已采纳
- 日期：2026-11-02
- 决策人：Mimo（用户）& 架构协作者
- 关联项目：oceanho-stack / services/iam-server（及官网/App/CLI 多端）

## 背景

多端（产品官网 / Console / 手机App / CLI）共用同一套后端 API，需要一个**稳定、自解释、可机器判断**的统一请求/响应协议，避免每端各自定义返回格式导致联调混乱。

## 决策

### 1. HTTP 语义

- **HTTP 200 统一承载业务结果**，业务对错看响应体里的 `code`。
- HTTP 401 / 403 / 404 / 500 只用于网关层与鉴权层的**传输级错误**（未登录、无权限、路由不存在、服务异常），不承载业务逻辑错误。
- URI 版本前缀：`/api/v1/...`。

### 2. 响应体

```go
type Resp[T any] struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Data    T      `json:"data,omitempty"`
    TraceID string `json:"trace_id"`
}
```

- 通用占位：无数据返回用 `Resp[any]{}`，`Data` 置 null 或省略。
- 业务错误时 `Data` 可为空，`Message` 给可读文案。

### 3. 错误码区间

| 区间 | 含义 |
|---|---|
| `0` | 成功 |
| `1xxx` | 认证（401 类：token 无效/过期/未登录） |
| `2xxx` | 租户（租户不存在/无权限/未选中租户） |
| `3xxx` | 校验（参数/业务规则校验失败，透出 xvalidator 错误） |
| `9xxx` | 内部错误（未预期异常） |

> 具体码值在 iam-server 的 pkg 内统一定义常量，本 ADR 只约定分段。

### 4. 分页

```go
type PageReq struct {
    Page     int    `json:"page" form:"page"`
    PageSize int    `json:"page_size" form:"page_size"`
    Sort     string `json:"sort,omitempty" form:"sort"`
    Order    string `json:"order,omitempty" form:"order"`
}
type PageResp[T any] struct {
    List     []T   `json:"list"`
    Total    int64 `json:"total"`
    Page     int   `json:"page"`
    PageSize int   `json:"page_size"`
}
```

### 5. Header 约定

| Header | 说明 |
|---|---|
| `Authorization` | `Bearer <token>`，认证 |
| `X-Tenant-Id` | 当前选中租户 ID，可空（切换租户时后端校验） |
| `X-Client-Type` | 端类型：`console` / `website` / `app` / `cli` |
| `X-Trace-Id` | 前端可传，后端兜底生成；用于链路追踪回传 |

### 6. 错误透出

- 参数校验错误统一 `code=3xxx`，`Message` 为 xvalidator 聚合的中文消息，`Data` 可带字段级错误明细（供表单回填）。

## 后果

优点：
- 多端对"成功/失败"的判断逻辑完全一致（只看 `code`）。
- 前后端协议稳定，OpenAPI / SDK 生成友好。
- trace_id 贯穿，排障方便。

代价 / 取舍：
- 业务错误不再使用 HTTP 状态码表达，需明确 code 语义表并维护。
- 对网关/代理的 HTTP 状态监控需另立口径（区分传输 vs 业务）。
