# 编码与规范（供 vibe coding / 协作者遵循）

> 本文件是 oceano-stack 各 Go 仓库的**统一编码规范**。新代码、新模块、AI 生成代码一律遵循，避免风格漂移。
> 适用仓库：go-libs（lib/）、iam-server（services/iam-server/）及后续 Go 项目。

## 0. 总原则

1. **先工具后业务**：通用能力先抽进 go-libs，业务项目只组装，不重复造轮子。
2. **分层边界是硬约束**：domain / dto / repository / service / handler / policy 各司其职（见 ADR-001）。
3. **可读性优先**：命名自解释，函数短小，不做过度抽象。
4. **测试必带**：每个库/模块有单元测试，改动不破坏既有测试。

## 1. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 包名 | 全小写，无下划线，单数 | `tenant`、`xlog` |
| 目录名 | 全小写 | `repository`、`xvalidator` |
| 导出的类型/函数 | 大写开头，驼峰 | `NewClient`、`TenantRepo` |
| 未导出 | 小写开头 | `newClient`、`msg` |
| 常量/枚举 | 大写驼峰（或 iota） | `CodeOK`、`ClientTypeConsole` |
| 接口 | 以能力命名，不加 I 前缀 | `Generator`、`Cache` |
| 错误 | 以 `Err` / `Error` 结尾 | `ErrNotFound`、`HTTPError` |
| 测试函数 | `Test` + 被测函数 | `TestSnowflakeUnique` |

## 2. 代码结构

- **函数保持短小**：一个函数只做一件事；超过约 30 行考虑拆分。
- **错误必须处理**：不吞错误；可用 `errors.Is` / `errors.As` 判等；包装错误用 `%w`。
- **尽早返回**：避免深层 if-else 嵌套。
- **切片/映射**：返回给调用方前考虑是否需要副本隔离（见 xcache 值拷贝）。

## 3. Query 链式返回副本（仓库层核心规范）

参照 ADR-001 与 my-repo-syncer 范式：

```go
func (q *TenantQuery) WhereNameLike(v string) *TenantQuery {
    cp := *q          // 复制结构体
    cp.NameLike = v
    return &cp        // 返回副本，不修改原对象
}
```

- **禁止**直接修改 receiver 再返回自身（`q.X = v; return q`）。
- 这样避免共享、复用、并发时条件被意外篡改，可安全地在 service 里多次组合。

## 4. 分层边界速查（见 ADR-001 详述）

- `domain`：纯模型，**禁止** import gorm / gin / casbin。
- `repository`：只做数据增删改查 + Query 条件收拢；**不写业务规则**；`*gorm.DB` 不外泄。
- `service`：持有 repo，做业务校验、权限、缓存、事务编排。
- `handler`：极薄，只做 dto 绑定 → 调 service → dto 映射 → 返回 xresp。
- 所有 `db.Where` 只在 repository 内出现。

## 5. 统一协议（见 ADR-003）

- 响应一律 `Resp[T]{code,message,data,trace_id}`；成功 `code=0`。
- 业务错误用 `1xxx` 认证 / `2xxx` 租户 / `3xxx` 校验 / `9xxx` 内部。
- Header：`Authorization`、`X-Tenant-Id`、`X-Client-Type`、`X-Trace-Id`。
- 分页用 `PageReq` / `PageResp[T]`。
- 参数校验错误统一 `3xxx`，透出 xvalidator 中文消息。

## 6. GORM 数据库无关（见 ADR-004）

- 不写数据库专属方言/类型。
- 一律走 xdb + 仓库 Query；service/handler 不碰 `db.Where`。
- 测试用 glebarez/sqlite 内存库 + 唯一 DSN。

## 7. 上下文与链路

- `ctx context.Context` 只承载 trace / 超时 / 取消。
- 业务身份（user_id / tenant_id / client_type）提取后封装 `AuthPrincipal` 传给 service，不直接依赖 gin 上下文工具。
- 日志用 xlog，`FromCtx(ctx)` 自动带链路字段；trace 用 xtrace。

## 8. 提交规范（git）

- 每个仓库独立提交、独立推送。
- commit message 用语义化前缀：
  - `feat(...)` 新功能
  - `fix(...)` 修复
  - `docs(...)` 文档
  - `refactor(...)` 重构
  - `test(...)` 测试
- 提交前必须：`go build ./...`、`go vet ./...`、`go test ./...` 全过。
- 新仓库、新库完成后同步更新 docs 仓库清单。
